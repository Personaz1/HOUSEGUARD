# Technical Profile — Personaz1

**Focus:** AI systems architecture, agent orchestration, automation, and system design.  
**Working mode:** Independent research and hands-on prototyping.  
**Portfolio:** A connected set of experiments and software projects; maturity varies by repository.

## Professional direction

I work at the systems level: decomposing complex goals into components, defining interfaces and responsibilities, connecting models with tools and external environments, and thinking through memory, state, feedback, orchestration, and failure handling.

My strongest area of interest is the architecture of AI-enabled systems rather than narrow model training or framework-specific application development. I am interested in roles where system design and implementation meet: AI Systems Architect, AI Automation Engineer, AI Agent Engineer, or technical prototyping/research roles.

This profile describes independent project work. It does not imply that every repository is production software, that every proposed capability is implemented, or that independent projects are equivalent to commercial team experience.

## What the portfolio demonstrates

- **System decomposition and architecture:** breaking broad concepts into components, interfaces, responsibilities, and staged development paths.
- **Agent orchestration:** persistent task loops, tool use, context handling, memory concepts, triggers, and coordination between model-driven and deterministic components.
- **AI integration:** exploring multi-model arrangements and the relationship between language models, tools, services, and real-world state.
- **Automation and connected systems:** designing interactions between software agents, home-automation platforms, sensors, and external services.
- **Research synthesis:** connecting ideas across software, formal reasoning, human-computer interaction, and embodied systems while keeping hypotheses separate from demonstrated results.
- **Technical communication:** documenting architecture, assumptions, limitations, unresolved questions, and project history.

## How to evaluate this work

For each project, inspect evidence in this order:

1. **Source code and commit history** — what was actually authored and when.
2. **Architecture and design documents** — what was intended and how the system was decomposed.
3. **Tests, examples, and reproducible experiments** — what can be independently verified.
4. **Status notes** — what is incomplete, proposed, archived, forked, or unverified.

The portfolio deliberately distinguishes:
- implemented behavior from planned functionality;
- model-generated decisions from deterministic orchestration;
- original work from upstream forks;
- empirical results from hypotheses and analogies;
- historical snapshots from actively maintained projects.

Some security-related repositories are archival research snapshots and are not presented as deployable products. Forked repositories retain upstream attribution and are not claimed as original work.
